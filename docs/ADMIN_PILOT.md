# Админка пилота — 16 октября 2026

## Для руководителя

1. Откройте FRchat, выберите `admin` и введите выданный пароль.
2. Нажмите красную кнопку «+ Новая публикация». Скопируйте сообщение в MAX и нажмите «Вставить из буфера». Если браузер запрещает буфер, удерживайте поле и выберите «Вставить».
3. Нажмите «Проверить»: программа подготовит заголовок, категорию, ссылки и даты. Поправьте только ошибочные пункты. «Время уточняется» не превращается в полночь.
4. Нажмите «Всё верно», затем «Опубликовать». После «Готово!» можно скопировать сообщение для MAX.

Для новой публикации после вставки достаточно трёх нажатий. При подозрении на повтор показаны старая и новая карточки рядом и три равнозначных действия: «Это повтор — напомнить», «Обновить старую», «Это новое». Напоминание требует подтверждения. Если появилась новая ссылка, дата или файл, предлагается обновление, чтобы сохранить дополнения. Для собрания из расписания предлагается добавить ссылку к конкретной дате. Подробности и проверки — в [правилах повторов](DUPLICATES.md). Файлы прикрепляются на первом шаге. Несколько вставок собираются в одну карточку.

Текст и прикреплённые файлы автоматически сохраняются на этом устройстве. Если вкладка закрылась, войдите снова и продолжите неопубликованный текст. При недоступном хранилище браузера приложение предупреждает, что вкладку нельзя закрывать. Пока идёт отправка, кнопка заблокирована; повтор после потери ответа не создаёт вторую карточку.

«Исправить» открывает карточку для изменений. «Удалить» требует подтверждения; вернуть запись можно сразу или в разделе «Удалённые». «Как видят участники» открывает обычную ленту собственника; наверху есть возврат к своим публикациям. Тема находится в «Настройках». «Как это работает?» повторяет три вводных экрана.

## Только для Алексея

Пароли находятся в исключённых из Git файлах `.local/PILOT_PASSWORDS.md` и `.local/pilot-accounts.json`. В таблице есть пустое поле «Кому выдан». Передавайте каждому участнику только его строку. Пароль администратора содержит 192 случайных бита (32 символа base64url); пользовательские пароли — 96 бит. Пароль admin открывает и чтение, и публикацию.

Настройка: [FRchat/#/setup](https://lesauteur.github.io/FRchat/#/setup), вход `admin`. Введите fine-grained токен: только `LeSauteur/FRchat-data`, Contents: Read and write. Для текущего эксперимента срок — 15.11.2026. Руководитель не использует эту страницу.

Токен находится только внутри отдельного зашифрованного объекта доступа admin в публичном репозитории данных. Объект зашифрован AES-256-GCM ключом PBKDF2-SHA256, 600 000 итераций, отдельная соль. Выведенные ключи остаются в памяти сессии. Пользовательские пароли открывают общий ключ чтения, но не объект admin. Общий ключ чтения также не открывает токен. Приложение не сохраняет токен открытым в browser storage и не экспортирует системную авторизацию gh. Заголовок авторизации отправляется только на api.github.com в пределах FRchat-data, перенаправления запрещены.

При истёкшем или отозванном токене руководитель видит «Публикация временно недоступна, напишите Алексею». Чтобы восстановить публикацию, выпустите такой же ограниченный токен и снова используйте `#/setup`. При замене пароля admin нужно перезашифровать его объект доступа; одной смены строки в локальной таблице недостаточно.

### Отозвать один пользовательский доступ

Сначала проверка без изменений:

```powershell
npm run access:revoke -- user3
```

Сам отзыв, когда это действительно потребуется:

```powershell
npm run access:revoke -- user3 --apply
```

Команда использует настроенный gh, свежий рабочий снимок и локальные пароли. Она убирает выбранный доступ, меняет ключ и epoch, заново шифрует все рабочие карточки и вложения, сохраняет пароли остальных участников и зашифрованное подключение администратора. Остальные входят повторно с прежними паролями. Если другой администратор изменил данные за это время, обновление ref без force отклоняется: рабочие изменения не теряются. Локальный пакет восстановления сохраняется до записи, поля «Кому выдан» не меняются.

Ранее скачанные данные и старую историю Git отозвать невозможно. Доступ отзывается к новым версиям данных. Во время этого прогона никто из user1–user5 не отозван: проверены сухой запуск и автоматический сценарий на искусственных данных.

## Запись и чтение

FRchat-data публичный. Содержание карточек, заголовки, имена файлов и индекс зашифрованы. Рабочие изменения данных записываются напрямую одним Git Data API коммитом: blobs → tree → commit → ref, `force:false`. Код FRchat публикуется через PR. Для переноса HEAD перечитывается свежий снимок, изменения разных постов объединяются; одна карточка сравнивается целиком. Если её изменили одновременно, программа просит выбрать текст. История сохраняется. Идентификатор операции защищает от двойного нажатия и потери ответа.

При реальной проверке обнаружена задержка raw URL ветки после успешного коммита. Поэтому один публичный запрос узнаёт текущий ref, после чего manifest и неизменные зашифрованные объекты читаются с raw по SHA коммита. Пароль и токен при чтении не передаются. Ref кешируется на устройстве на минуту; ручное обновление проверяет его заново. Если публичный API или raw недоступен, остаются raw ветки и встроенная резервная копия пилота. Последняя может быть старой; приложение показывает предупреждение при переходе к встроенной копии. Фонового опроса нет. Публичный API имеет общий лимит для внешнего IP, поэтому массовый запуск потребует наблюдения за резервным режимом.

`npm run pilot:data` после перехода на отдельные доступы блокируется, чтобы старая пересборка не уничтожила рабочие записи или аккаунты. Новые импорты должны быть отдельной миграцией из свежего рабочего снимка.

## Исправление исходного наполнения

Все изменения внесены в локальный `samples/seed/build_seed.py`, seed пересобран и сверён с зашифрованным набором. Исходники содержат персональные данные и остаются вне Git. Читаемый фактический diff данных до/после — `.local/seed-review.diff`, повторное построение — `node scripts/report-seed-diff.mjs`.

- Еженедельное собрание офисов и Комиссия по этике: «Напоминания». Из «Горит» исключены; на главной свернуты в один раздел. В календаре по умолчанию скрыты, включаются явным выбором. Разовые собрания и форум остаются «Собраниями».
- Египет: срок списков 2 октября, 16:00. 25 октября — 20 ноября является ориентировочным окном вылета, а не непрерывным событием. Ложное событие убрано.
- «До 25 сентября включительно» и «До конца 30 сентября»: all-day дедлайны на названном дне. После срока — 24 часа с пометкой «Срок истёк», затем архив.
- Октябрьский состав комиссии ограничен октябрём. Окно во вторник не означает, что комиссия назначена: это явно написано в подписи. Пятничный срок и вторничное окно являются разными датами.

Неизвестное расписание курса, пять отсутствующих файлов и ссылки из первоначального seed-review эта работа не подменяет догадками. Подтверждённый телефон с окончанием 6405 сохранён в локальном источнике.

## Проверка перед показом

Публичные снимки используют только искусственный текст: `docs/qa/*-admin-*.png`. Матрица: 390 и 1280 px, обе системные схемы и оба ручных переопределения. Проверяются контраст (axe-core + расчёт), шрифт от 16 px, кнопки от 48 px и отсутствие горизонтального переполнения. Отдельно: восстановление черновика, отсутствие сети, истёкший доступ, повтор после ошибки, двойное нажатие, напоминание, удаление и возврат. Реальные снимки пилота и результат проверки ограниченного токена находятся только в `.local/admin-real/`.

Это проверка браузера с шириной телефона. Физический телефон, мобильные сети РФ без VPN и встроенный браузер MAX требуют очной проверки; измеренное время автоматизации не является временем выполнения неподготовленным человеком.
