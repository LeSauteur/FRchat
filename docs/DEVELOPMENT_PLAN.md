# Единое пространство «Домиан Франчайзинг»: дорожная карта

Редакция: 13 ноября 2026. Первый интерфейс разрешён и реализован локально в ветке feature/unified-franchise-workspace. [Пакет просмотра и проверки](WORKSPACE_PREVIEW.md). Публикация, миграции и массовая выдача доступов не разрешены этим документом.

Заменяет устаревший план «пилот до редактора» от 15 октября. Прежний текст сохранён в истории Git и локальном пакете аудита. Реализованные функции не относятся к будущим работам.

Основания: текущая постановка пользователя и аудит реализации. Подробности: [план первого выпуска](FIRST_RELEASE_PLAN.md), [инвентаризация](IMPLEMENTATION_AUDIT_2026-11-13.md), [архитектура](UNIFIED_SPACE_ARCHITECTURE.md), [доступы и публикация](ADMIN_PILOT.md), [сроки](DEADLINES.md), [напоминания](REMINDERS.md), [дубли](DUPLICATES.md).

## 1. Цель и границы

FRchat развивается в точку входа единого информационного пространства франшизы. Приоритеты тестирования: понятная навигация, единое место для документов, быстрый поиск, важные сообщения и действия со сроками.

| Раздел      | Содержание                                                                       | Основа                                                          |
| ----------- | -------------------------------------------------------------------------------- | --------------------------------------------------------------- |
| Новости     | Сообщения ЦО, объявления, изменения, история, избранное и архив                  | Текущие лента, карточки и редактор                              |
| Календарь   | События, отчётность, сроки, напоминания, ближайшие действия                      | Текущая модель дат и календарь                                  |
| Документы   | База знаний, регламенты, договоры, бланки, логотипы, шаблоны, инструкции и поиск | Справочник, вложения, шифрование; отобранные результаты ревизии |
| Инструменты | Переходы к калькуляторам, мотивации, рабочим сервисам и «7 дням»                 | Новый каталог переходов к самостоятельным приложениям           |

Первый этап объединения — общая точка входа и навигация. Он не требует объединять репозитории и базы данных, переносить приложения, внедрять SSO или искать по всем внешним системам. «7 дней» остаётся самостоятельным; существующий блок задачи дня сохраняется.

Исключены: полноценная CRM, бухгалтерская система, универсальный мессенджер, сделки, кадровый учёт и сложное управление проектами. Тематическое обсуждение конкретного материала возможно позже, после отдельного решения.

## 3. Согласованные решения, которые сохраняются

Сжатие истории Git исключено из текущей разработки. Автоматическая необратимая очистка, массовое создание учёток и миграция не выполняются в рамках объединения навигации. Внешняя проверка проводится на содержательных вехах, а не как обязательная остановка после каждого мелкого PR.

1. Переиспользовать React/Vite/TypeScript и существующие доменные модули. Не переписывать сервис и не объединять репозитории ради общей навигации.
2. Рабочие данные и файлы — зашифрованные объекты FRchat-data: AES-256-GCM, PBKDF2-SHA256 от 600 000 итераций, случайные соли/IV, SHA-256 и сессионный ключ в памяти.
3. Запись — blobs → tree → commit → ref без force. При сдвиге ref перечитать актуальные данные. Разные записи не теряются; конфликт одного поста не разрешается молчаливой затиркой. Повтор запроса не создаёт дубль.
4. Сохраняются id, история, связи, напоминания, ссылки на экземпляры серий, статусы закрытия/отмены/переноса, обратимое удаление и черновики. Повтор не создаёт копию; выбор напоминания не уничтожает вставленный текст и файл.
5. Все сроки — Europe/Moscow. Истёкший срок не делает следующий просроченным. После последнего срока — 24 часа до архива; событие заканчивается в end или start + 2 часа; серия — после последнего экземпляра.
6. Подсветка 72–24 часа только визуальная; «Горит» — 48 часов, последние сутки ярче. Ручное напоминание поднимает карточку, возвращает непрочитанность, хранит выбранный срок. Повтор менее 12 часов требует предупреждения.
7. Действующие логины/пароли сохраняются до адресного решения. Новая навигация не запускает ротацию ключей, массовую выдачу или изменение формата данных.
8. В публичных исходниках и CI нет паролей, токенов, внутренних документов и реальных снимков. Старую историю Git и скачанные данные невозможно отозвать задним числом.
9. Все пути lesauteur.github.io имеют общий origin. Префиксы storage не изолируют секреты. Сторонние аналитика, виджеты и исполняемые зависимости — только после отдельной проверки.
10. Код — через ветку, PR, зелёный QA и Pages deploy; рабочие данные — отдельной атомарной записью. Обновление этой документации не разрешает публикацию сервиса.

## 4. Этапы, зависимости и готовность

Первый полезный выпуск объединения — П1 вместе со стартовым наполнением П2. Разработка интерфейса и сбор документов независимы: интерфейс проверяется на искусственных материалах, не ожидая реальных файлов. Наполнение утверждёнными материалами начинается после проверки интерфейса. Четыре пункта меню сами по себе не означают готовое информационное пространство для всей сети.

| Этап                          | Приоритет                          | Зависимости                                                   | Результат                                                                     | Критерий завершения                                                                                                     |
| ----------------------------- | ---------------------------------- | ------------------------------------------------------------- | ----------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------- |
| П0. Непрерывность             | P0, срочно                         | Решение владельца о замене ключа                              | Рабочая публикация, реестр и восстановление                                   | Ключ отдельно обновлён до истечения; доступы и посты сохранены; резерв проверен                                         |
| П1. Единая точка входа        | P1                                 | Утверждение концепции и списка сервисов                       | Четыре раздела и переходы к самостоятельным приложениям                       | Старые ссылки и 15 входов работают; поиск новости/срока и переход к инструменту понятны на телефоне                     |
| П2. Полезные документы        | P1, основной содержательный этап   | П1; владелец материалов и одобренный набор                    | Документы и знания в одном месте                                              | Настоящие материалы найдены и открыты/скачаны; понятны актуальность и ответственный; внутренних документов в public нет |
| П3. Основной путь: П0 → П1 → П2 → П4. Проектирование П3 возможно параллельно П1/П2. Журнал активности, права и уведомления должны опираться на совместимый механизм идентификации, а не независимые списки пользователей.

Расширение аудитории — самостоятельное решение. Поимённая выдача уже возможна служебным процессом без редактирования кода и не требует ждать всех будущих функций. В этом аудите новых записей нет.

## 5. Конкретная последовательность внедрения

### П0. Доступы и эксплуатация

Аудит выполнен без изменений; последующая разрешённая замена ключа через #/setup завершена 13 ноября. Доступ ограничен FRchat-data, Contents: Read and write. Изменились только manifest и зашифрованный объект admin; пароли, ключ чтения и индекс сохранены. Токен не пересылался в чат, не помещался в URL или исходники. Старый ключ отозван 13 ноября после подтверждения владельца: GitHub отвечает 401, новый ключ продолжает приниматься.

Сверить получателей user1–user5 в локальном реестре «Кому выдан». ФИО не назначать догадками; выданные логины не переименовывать без решения. Подготовить защищённый резерв реестра и инструкцию восстановления. Название «временные» не является причиной массового сброса.

### П1. Общая оболочка

- **PR1.1:** выделить оболочку, маршруты и экраны из src/main.tsx без смены поведения. Сохранить storage-ключи, загрузчик, редактор, шифрование и темы.
- **PR1.2:** четыре раздела. Избранное и архив — видимые элементы «Новостей», без скрытого «Ещё»; справочник и файлы — внутри «Документов». Старые #/feed, #/favorites, #/archive, #/reference, #/files и #/post/<id> продолжают открываться.
- **PR1.3:** каталог инструментов с назначением и проверенной ссылкой. «7 дней» обязательно; калькуляторы, мотивация и другие сервисы — только из согласованного реестра. Без iframe, копирования приложений и передачи паролей.

До изменения интерфейса согласовать название пространства, порядок карточек, список инструментов и конкретный макет. Старые права и рабочее хранилище не меняются. Отсутствующие материалы имеют честное пустое состояние.

### П2. Документы и база знаний

- **PR2.1:** единый экран поверх справочных постов и вложений. Разделы: база знаний, регламенты, договоры, бланки, бренд/логотипы, шаблоны, инструкции. Переиспользовать Post/reference, FileEntry, Attachment/download и текущий поиск.
- **Отдельная контентная веха:** владелец отбирает материалы и подтверждает актуальность, аудиторию и допустимость распространения. FrDomianReview — источник проверенных результатов и стабильных id, а не готовый каталог к автоматической публикации. Наполнение выполняется только после разрешения на запись данных.
- **PR2.2, когда потребуется:** самостоятельная карточка документа, теги, ответственный, дата актуальности, действующая версия и «заменён/архив». Аддитивная схема, проверка всех писателей, отдельный план изменения данных. Старые записи сначала остаются источниками через адаптеры.

Поиск первого выпуска: названия, описания, теги, имена файлов. Полнотекстовое извлечение PDF/Office и OCR оцениваются отдельно. Критерий: утверждённые реальные документы находятся по названию/рабочему слову и открываются на телефоне; нет фиктивных файлов. Простое число карточек не заменяет содержательную готовность.

### П3. Управление доступами без правки кода

Следующий приоритет после интерфейса и до массового подключения: панель владельца — ФИО, логин, роль, статус, выдача, восстановление и отзыв. Переиспользовать контейнеры доступа и атомарную запись. Нужен отдельный ADR по ключам: сейчас полный отзыв использует локальные пароли остальных учёток и меняет epoch/ключ данных.

Простая кнопка «отключён» или удаление строки из нового manifest не отзывает общий ключ, извлечённый из старой версии доступа. Варианты: обёртки ключей под отдельным ключом владельца либо минимальный доверенный сервис доступа. Сравнение и рекомендация — в [архитектуре](UNIFIED_SPACE_ARCHITECTURE.md#6-доступы-и-роли).

Владелец/редактор/читатель — будущая модель. Скрытая кнопка не ограничивает человека с Contents: write на весь data-репозиторий. Настоящее разделение полномочий проверяется доверенным механизмом. Действующие пароли сохраняются; восстановление владельца обязательно.

### П4. Поиск и ближайшие действия

Текущая нормализация поиска переиспользуется; внешние источники подключаются по одному адаптеру. Сначала доступные метаданные, затем при необходимости полный текст. «Общий поиск» нынешней версии означает только FRchat.

Ближайшие действия сначала вычисляются из существующих сроков: что сделать, когда, где форма/инструкция. Событие и срок остаются разными типами. Персональное выполнение, назначение офису и синхронизация между устройствами — отдельная модель, а не поле общего поста.

FRchat не записывает прогресс «7 дней» напрямую в localStorage. Глубокая интеграция начинается с документированного контракта и версии данных; общий origin его не заменяет.

### П5. Уведомления, наблюдение, тематические обсуждения

Ручные напоминания и визуальное выделение уже готовы. Фоновая доставка требует отдельно выбрать каналы, настройки получателей, часовой пояс, дедупликацию, повторы при сбое и обработку отзыва. Таймер цвета карточки не выполняет фоновую отправку.

Центральный журнал посещений пока отсутствует. Нужны достоверная привязка к учётке и закрытый приёмник событий. Открытие карточки — просмотр, не подтверждённое прочтение. Пароли, тела документов и запросы поиска в журнал не отправлять. Стороннюю аналитику не добавлять.

Тематический чат — только по отдельному решению: обсуждение новости/документа/задачи с правами и модерацией. Универсальная переписка, звонки и замена MAX не входят в продукт.

## 6. Общие критерии готовности

- Действующие входы и ссылки сохраняются. При согласованной смене ключей проверяются совместимость и восстановление; интерфейсный PR их не меняет.
- Для изменений данных сравниваются id, количество записей, история, ссылки и хэши файлов; успех скрипта сам по себе недостаточен.
- 390/430/1280 px, обе темы и ручной переключатель; поля от 16 px, основные нажатия от 48 px, текст 200% без переполнения.
- Сохраняются текущие тесты; новые — на изменяемые правила. Браузерный QA на искусственных данных. В build/CI нет приватных исходников и секретов.
- Проверяются неверный пароль, недоступный источник, запрет storage, потеря ответа, двойное нажатие, восстановление черновика. Серверные функции получают отдельные тесты прав.
- Реальные iPhone/Android, MAX и мобильные сети проверяются отдельно: viewport-эмуляция этого не доказывает.
- Откат интерфейса не переписывает данные. Для новой схемы — репетиция на копии, сравнение целостности и защита от старого writer, который не сохраняет новые поля.

5. Массовая выдача доступов и любые миграции требуют отдельного прямого поручения.

## 8. Публикация после разрешения

Штатный порядок: `git push -u origin <ветка>` → `gh pr create --base main --head <ветка>` → `gh pr checks <PR> --watch --interval 10` → `gh pr merge <PR> --merge --delete-branch` → `git checkout main` → `git pull --ff-only origin main` → `gh run list --limit 5` → `gh run watch <ID_RUN_DEPLOY> --exit-status`.

При сбое: `gh run view <ID> --log-failed`, исправление причины и повтор того же процесса. Без прямого push в main, смены origin, временных deployment remote, Sites, hosting-конфигурации, ручных Authorization-заголовков в Git и интерактивной авторизации.

В документальном шаге нет push, PR, deploy, выдачи доступов или миграций. Отдельно разрешённая замена ключа публикаций выполнена через рабочую настройку; она не разрешает внедрение новой навигации.
