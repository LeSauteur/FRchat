# FRchat — план разработки, редакция после REVIEW-01 и ADDENDUM-02

Дата: 15.10.2026. Исполнитель — Codex. Внешняя проверка — Claude.

Обновление 16.10.2026: реализована экспериментальная админка руководителя и отдельные доступы admin/user1–user5. Актуальные правила подключения, хранения пароля/токена, атомарной записи, отзыва доступа, исправлений seed и проверки — [ADMIN_PILOT.md](ADMIN_PILOT.md). Новые решения пользователя имеют приоритет над исходным планом ниже: токен хранится в data-репозитории под длинным паролем admin; черновики вложений шифруются в IndexedDB; руководитель проходит три шага без технических настроек. Рабочее хранилище — публичный FRchat-data, чтение по SHA коммита. Следующая проверка — наблюдение за самостоятельной публикацией руководителем с физического телефона.

Дополнение по отзыву пилота: после исправления и публикации обеих тем — отдельный PR с избранным (ID в localStorage, звёздочки, свой раздел и фильтр) и постоянным справочником (пять категорий, общий поиск, зашифрованный seed, честное пустое состояние). Редактор остаётся следующей вехой. Подробности реализации и формата: [FAVORITES_REFERENCE.md](FAVORITES_REFERENCE.md).

## Текущий приоритет: пилот до редактора

Первая веха — работающее приложение для руководства и выбранных собственников на **46 реальных публикациях** за 15.09–15.10.2026 из `samples/seed/frchat-seed.json`. Календарь входит в пилот. Статусы считаются по текущему времени, без режима подмены даты.

Стек: React, Vite, TypeScript; небольшие общие JS-модули домена и WebCrypto для Node и браузера; `node --test`. Исходная папка FRchat — единственное место изменений. Пользователь отдельно поручил публикацию пилота в созданный `LeSauteur/FRchat`; выполняется штатный PR/QA/Pages-процесс.

## Принятые решения пользователя

- Код FRchat и любые изменения domian-7-days — отдельная ветка → PR → зелёные проверки → merge → проверка deploy, строго по глобальному порядку. Рабочие данные приложение пишет напрямую в отдельный data-репозиторий.
- Рабочая запись: Git Data API, blobs → tree → commit с parent текущего HEAD → ref без force. При сдвиге ref перечитать, слить и повторить. До переключения ref частичные blobs не становятся опубликованным снимком.
- «Завершить» — `state=closed`, `closed_at`, сразу архив, запись истории. Просроченный дедлайн остаётся актуальным 24 часа с красной плашкой. Событие заканчивается в `end` или через два часа после `start`. Несколько событий архивируются после последней даты. Открытая недельная серия не архивируется после первого экземпляра.
- PBKDF2-SHA-256 не менее 600 000 итераций, AES-256-GCM, случайная соль от 16 байт, новый IV 12 байт на каждое шифрование, тег 128 бит. Ключ выводится один раз при входе и остаётся только в памяти сессии.
- Реальные ФИО, тексты, телефоны, ссылки и имена файлов — только в `samples/` или зашифрованном хранилище; без открытых фикстур, логов, CI и артефактов с цитатами.
- Подтверждённый пользователем телефон курса внесён в локальный `build_seed.py` и пересобран через него. Сам номер не дублируется в этой документации или исходниках приложения.

## Упрощения из REVIEW-01

Приняты A1–A9 с уточнениями нового порядка ADDENDUM-02:

1. Пилот до редактора. Полезный результат появляется после чтения и интерфейса, без ожидания всего этапа 1.
2. Конфликт — на уровне поста целиком. Разные посты, история и напоминания объединяются по id; две изменённые версии одного поста показываются админу для выбора. Межполевого слияния нет.
3. По последнему критерию «ничего не потерять» черновик текста и полей шифруется в localStorage, вложения — в IndexedDB. После восстановления вкладки они загружаются автоматически. При запрете хранилища браузера показано предупреждение.
4. Для комиссии достаточно вычисляемого правила пятницы перед вторником. Seed уже содержит согласованные серии пятницы и вторника, импорт сохраняет их.
5. Первый редактор распознаёт частые форматы дат, остальные вводятся вручную. Все форматы ANALYSIS должны быть покрыты до закрытия этапа 1. Ручной многодневный календарь seed работает уже в пилоте.
6. Ротация — обслуживание и остановка при изменении HEAD; без сложного включения параллельных изменений.
7. Сжатие истории полностью убрано из разработки v1. В README описывается рост репозитория и предел отзыва старых копий; возвращаемся к теме при существенном объёме, например 500 МБ.
8. Внешнее ревью на трёх вехах: крипто/чтение, пилот перед реальным использованием, завершение этапа 1 с редактором и протоколом записи. Промежуточные шаги проверяет Codex.
9. Путь объекта — SHA-256 шифротекста. При рабочей записи неизменённый объект переиспользуется по существующей ссылке. Одинаковый открытый текст, зашифрованный заново со случайным IV, даст другой хэш: одного content-addressed пути недостаточно для дедупликации. Неизменённые объекты нельзя без причины перешифровывать.

## Порядок реализации

### П1. Каркас и границы приватности

Локальный Git, ветка `pilot-reader`, React/Vite/TS, русская навигация, тёмная тема, manifest/иконка/theme-color. Отдельные `src/lib` для модели, времени, шифрования, фильтров, загрузки. CI на синтетических unit-тестах и сборке без seed. `samples`, `.local`, результаты браузерных проверок исключены из Git; для публикации шифротекст пилота включён в Git. Dev-сервер не обслуживает приватные каталоги.

### П2. Импорт seed и доменная модель

Конвертер `frchat-seed/1` → `schema_version=1`. Сохраняются стабильные id, категории, тексты, source, author, даты, серии, ссылки по экземплярам, напоминания, история, related, expires_at и дни рождения. У закрытого поста closed_at берётся из события history=closed, иначе updated_at. `review_notes` и `origin_message_ids` удаляются из читательской модели. Ожидаемое вложение содержит только label и отображается как «Файл будет добавлен».

Для all-day конец диапазона исключающий; all-day дедлайн истекает в начале следующего дня МСК. Даты/периоды фильтруются в МСК независимо от часового пояса устройства. Для отмены/переноса календарь сохраняет зачёркнутую исходную дату. Ссылка конкретной недели не переносится на следующую.

### П3. Шифрованное хранилище и вход

`scripts/build-pilot-data.mjs` читает seed и необязательную карту файлов, создаёт случайный код в `.local/pilot-access-code.txt`, шифрует index + месячные блоки + файлы. Код не передаётся через аргументы команд, URL, Git или вывод инструментов.

Итоговый формат:

```text
manifest.json                           только технические параметры KDF/epoch/index-ref
objects/<sha256-шифротекста>.bin          зашифрованные index, месяцы и вложения
```

Индекс внутри шифрования содержит категории, дни рождения, период, число публикаций и ссылки на месяцы. Месяц — по дате первоначального создания; есть августовские/ранние сентябрьские оригиналы, повторённые в целевом периоде. Это правильно: фильтр публикаций по периоду не должен переписывать исходную created_at.

Контейнер FRC1: magic + длина заголовка + JSON заголовка + ciphertext с GCM tag. Заголовок (schema/epoch/objectId/IV) целиком аутентифицируется через AAD. Путь берётся из хэша уже зашифрованных байтов; AAD не включает этот путь, чтобы не создать циклическую зависимость. Перед расшифровкой проверяется SHA-256 объекта.

Для локального пилота результат находится в `.local/pilot-data/` и `public/pilot-data/`; только шифротекст попадает в dist. Это убирает зависимость от создания нового репозитория до проверки интерфейса. Формат совпадает с будущим data-репозиторием, его перенос меняет только `public/config.json`. При подготовке локальной версии эти каталоги не коммитились автоматически. Для порученной публикации public/pilot-data включён в Git после проверки шифротекста; .local остаётся исключённым. Нет скрытой публикации или нового remote.

Ручной ввод кода. «Запомнить» сохраняет код по требованию PROMPT с try/catch; при запрете storage работа идёт в памяти. «Забыть код и выйти» удаляет код и освобождает читательскую сессию. На первом открытии загружаются все три маленьких месячных блока, поэтому поиск охватывает все 46 публикаций.

Внешнее ревью №1: контейнер, код, производительность PBKDF2, отсутствие plaintext, режимы чтения и проверки повреждённых объектов.

### П4. Интерфейс пилота

Ориентир — `docs/mockup/frchat-concept.png`: тёплый светлый фон, красный бренд, спокойные карточки, контрастные подписи, нижняя навигация телефона. На широком экране — боковая навигация и сетка карточек.

- «Актуально»: задача дня, дни рождения, «Горит», закреплённое, роялти/мотивации, рабочая лента.
- Карточка: полный текст/безопасные ссылки, даты, ссылка встречи на конкретный экземпляр, история и напоминания, связанные карточки, файлы, копирование постоянной ссылки.
- Календарь: месяц, неделя, повестка на 14 дней, все сеансы и многодневные события, недельные серии, дедлайны. Выбор дня показывает события. События будущих дат после 15 октября тоже видны, если они объявлены в выбранных публикациях.
- Архив и общий поиск: ё=е, source, заголовок, текст, имена файлов. Мультивыбор категорий, периоды, тип даты, статус, важность, файлы; фильтры в hash-URL.
- «Файлы»: реальные доступные вложения и пять явно обозначенных ожиданий, без имитации скачивания отсутствующих Excel.
- «Обратная связь»: настраиваемая ссылка в config. Пока адрес не задан — окно составления/копирования отзыва, без самовольной отправки.
- Плашка «Пилот · данные на 15.10.2026», локальное прочтение по ревизии, кнопка «Добавить на главный экран» с инструкцией.

Пока внешний JSON 7 days не разрешён отдельным PR, блок использует честную ссылку на существующий чек-лист текущего московского дня. Темы и promise не выдумываются; адаптер готов читать JSON, когда он появится. Не исполняем внешний days.js и не копируем его тексты. Прогресс v3 только читается; неизвестная версия/другой origin — без прогресса.

Внешнее ревью №2: пилот перед раздачей руководству и собственникам, реальные телефоны/сети и спорные данные. Публикация — только отдельная задача и штатный PR-процесс.

### П5. Редактор и рабочая запись — после пилота

Мобильные кнопки «Добавить ещё текст» и «Выбрать файлы»; безопасная обратимая очистка MAX; подсказки категории, заголовка, дат и ссылок; ручная коррекция; дубли с выбором новая/обновить/напомнить; предпросмотр, публикация, анонс для MAX.

Все действия карточки: срок, закрепление, ссылка, отмена, перенос, завершение, корзина, восстановление. Git Data API публикует индекс/месяцы/файлы одним коммитом, ref только fast-forward. Обработка конфликтов целых постов и повторной попытки после потери ответа. PAT пока только sessionStorage; хранение под PIN требует явного ответа пользователя.

Далее — оставшиеся форматы парсера, кандидаты удаления (90/180/никогда от момента архивации), корзина 30 дней и подтверждаемая очистка при входе админа, двойное подтверждение защищённых категорий. Ротация в режиме обслуживания и остановка при сдвиге HEAD.

Внешнее ревью №3 перед закрытием этапа 1: Git Data API, два админа, удаление/восстановление, весь парсер, мобильная публикация, ротация и документация.

### П6. Остальные функции этапа 2

ICS с напоминанием; каталог постоянных шаблонов и версии файлов; «Заменено новым»; семь зашифрованных инфографик задачи дня. Календарь и дни рождения уже входят в пилот. Сжатие истории, бот MAX, комментарии, push, кабинеты и справочник офисов не входят в эту реализацию.

## Проверки и критерии готовности пилота

1. Все 46 id, тексты, даты и четыре недельные ссылки проходят преобразование/шифрование/расшифровку без потерь; заметки и id исходных сообщений читателям недоступны.
2. Unit: МСК, 24 часа, +2 часа, последняя дата, несколько сеансов, all-day, недельные ссылки и исключения; поиск и периоды; неправильный ключ, изменённый ciphertext/AAD, разные IV, проверка минимального PBKDF2.
3. Production build: типы, отсутствие plaintext из seed, секретов и samples в dist. CI работает без реальных данных.
4. Браузер: вход, сохранение/выход, ссылка карточки, поиск/фильтры, месяцы сентябрь/октябрь, неделя, повестка, архив, mobile 360/390 px, темы, отсутствие горизонтальной прокрутки и критических ошибок.
5. Реальные Android/iOS и встроенный браузер MAX: сохранение кода и переход во внешний браузер проверяет человек на устройствах. Локальная автоматизация не заменяет эту проверку.
6. Мобильные МТС/Билайн/МегаФон/Т2 и офисный Wi-Fi без VPN: человек проверяет источники. Локальный сетевой запрос не доказывает доступность у каждого провайдера.

## Оставшиеся решения и реальные ограничения

- Для пилота выбран ручной ввод кода; приглашение с кодом в URL не реализуется без явного решения. PAT/права редактора пока не нужны.
- Доступ пилота уже определён: руководство + выбранные собственники. Массовый доступ руководителей вне пилота остаётся отдельным решением.
- Изменение domian-7-days для JSON требует согласия и отдельного PR. PDF там не меняется. Тексты дней из чужого скрипта в FRchat не копируются.
- Версия расписания курса 7 октября ещё не подтверждена. Пока сохранена версия seed, служебная заметка остаётся локальной. Телефон пользователь уже подтвердил и он исправлен.
- Пять Excel и две ссылки отсутствуют. Не выдумываем файлы/URL, ничего не отправляем другим людям. Вложения подключаются через локальную карту files/attachments.json.
- У рефералов сохраняется известный старый дедлайн: на текущую дату публикация честно в архиве; новый срок без решения не назначается.
- Общий origin: не подключать Метрику/сторонние скрипты ни на одном сайте `lesauteur.github.io`. Они получают доступ к сохранённому коду. CSP через meta не обеспечивает frame-ancestors.
- Загрузчик поддерживает список источников с проверкой хэша: для пилота same-origin; при отдельном хранилище raw → Pages данных → при необходимости CDN с зафиксированной версией. Зеркала нужно реально включить и проверить; не обещаем несуществующий резерв. Для стабильного manifest CDN без точной версии не подходит.
- Раздача кода — отдельно через локальный файл. Шифрование с общим кодом не даёт индивидуального отзыва; Git-история и скачанные копии не исчезают при ротации. Неизменённые файлы и старые версии контролируются ссылками текущего снимка.

## Публикация

Публикация пилота отдельно поручена пользователем. Код проходит только глобальный порядок: `git push -u origin <ветка>` → `gh pr create --base main --head <ветка>` → `gh pr checks <PR> --watch --interval 10` → `gh pr merge <PR> --merge --delete-branch` → `git checkout main` → `git pull --ff-only origin main` → `gh run list --limit 5` → `gh run watch <ID_RUN_DEPLOY> --exit-status`.

Не менять origin, не добавлять deployment remote, не создавать .openai/hosting.json и не публиковать через Sites. При ошибке входа обычного git/gh сообщить её, без интерактивной авторизации.
