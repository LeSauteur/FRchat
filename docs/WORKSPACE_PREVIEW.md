# «Домиан Франчайзинг»: первая локальная версия

13 ноября 2026. Ветка feature/unified-franchise-workspace. Это рабочая реализация для просмотра, без push, merge и изменения сайта. Реальных материалов в демонстрации нет.

## Просмотр

Локальный адрес: [127.0.0.1:4185](http://127.0.0.1:4185/). Доступен на этом компьютере, пока запущен процесс просмотра. Размещённый FRchat продолжает работать отдельно.

| Учебный вход | Искусственный пароль    | Назначение                             |
| ------------ | ----------------------- | -------------------------------------- |
| user1        | qa-reader-password-only | Просмотр участником                    |
| admin        | qa-admin-password-only  | Управление материалами и инструментами |

Эти пароли относятся только к искусственной демонстрации. Они не совпадают с выданными рабочими доступами. Данные демонстрации хранятся в памяти её процесса; перезапуск сбрасывает тестовые записи. В админке используйте «Документы и инструменты», для просмотра участником — «Как видят участники».

Для повторного запуска из корня FRchat:

```powershell
npm run build
npm run preview:workspace
```

Нужен установленный Node.js, Python не используется. Локальный контур просмотра не является новым сервером продукта: он обслуживает сборку и искусственный Git Data API в памяти. Слушает только 127.0.0.1, не использует реальные токены, блокирует внешние fetch-запросы и не записывает в GitHub. Существующая производственная сборка этот контур не включает.

## Что реализовано

- Четыре направления в одной оболочке. Телефон: четыре видимые подписи без меню «Ещё». Компьютер: боковая навигация.
- Рабочая сводка: важное, отдельные именованные сроки, отдельные ближайшие события, счётчик «Горит», быстрые переходы. На телефоне сроки идут раньше объявлений. Ниже сохранены задача дня и прежняя лента с напоминаниями, сортировкой, поиском и фильтрами.
- Новости: архив и избранное доступны явно. Общий поиск по новостям, архиву и документам доступен из всех разделов; поддерживает описание и ответственного за документ.
- Календарь переиспользован; добавлены ближайшие действия. Срок и событие не смешиваются. Даты и конец дня остаются московскими.
- Документы: категории, собственный поиск, каталог статей/файлов, актуальность, ответственный, версия. Материал читается как статья с телефона; вложения скачиваются после расшифровки и проверки хэша. PDF, безопасные изображения и plain text могут открываться отдельно; Office скачивается без обещания встроенного просмотра. Есть ожидаемые вложения и явное состояние «файл пока не добавлен».
- Инструменты: проверенная ссылка на «7 дней», назначение, отдельная вкладка без передачи пароля. Редактор позволяет добавлять и менять HTTPS-ссылки, скрывать их; идентификаторы пригодны для будущих адаптеров.
- Управление содержимым: документ, категория, описание, актуальность, ответственный, версия, текст и файлы. Категории можно добавлять, переименовывать и скрывать для новых материалов. Файлы можно перевести в прежние версии и вернуть в действующие. Удалённый материал возвращается через прежний механизм удалённых публикаций.
- Черновики текста и файлов шифруются на устройстве. Проверено восстановление после перезагрузки и повторного входа admin. При недоступности хранения отправка не скрывает проблему. Повтор после сбоя не создаёт дубль. Если запись уже изменилась на другом устройстве, требуется явный выбор версии.

## Совместимость и границы

Post.type=reference сохранён. Опциональные метаданные document хранятся в том же зашифрованном месячном объекте. Категории и инструменты — специальная зашифрованная reference-запись frchat-workspace-settings, workspace.version=1. Новая архитектура хранения, серверная авторизация или публичный каталог внутренних метаданных не вводились. Обычные записи без этих полей продолжают читаться.

Прежние файлы остаются в attachments с superseded_at/version_label, поэтому стандартная ротация доступа обрабатывает и их. Это сохранённые версии файлов, а не полноценная система согласования или отката всего документа. Каталог настроек сохраняется атомарно как одна запись с проверкой конкурирующего изменения.

Ссылки #/feed, #/post/id, #/calendar, #/favorites, #/archive, #/reference, #/files и административные маршруты сохранены. Категории по старым адресам работают после перезагрузки. Добавлены #/documents, #/tools, #/admin/content и #/admin/document/id. Существующие ключи storage и логины не переименовывались.

Новых рабочих аккаунтов нет. Все 15 доступов открыты прежними паролями; рабочий индекс содержит 77 записей. Единственная разрешённая операция с реальными данными перед разработкой — настройка нового ключа; после неё HEAD FRchat-data остался прежним. Старый ключ отозван, новый продолжает приниматься. В уже открытой со старым ключом админке может потребоваться повторный вход прежним паролем.

## Проверки

- 49 модульных тестов: прежние 43 и 6 новых. Среди новых — метаданные, импорт категорий, сохранение/чтение, конкурирующая запись и ротация с текущими/прежними файлами. Ротация выполнялась только на искусственном хранилище.
- TypeScript, production build, проверки публичных зашифрованных контейнеров и приватности сборки — успешно.
- Общий браузерный прогон прежних сценариев: 12 проверок сроков, 30 напоминаний, 132 проверки редактора, 18 сценариев дублей, 6 проверок читаемости; 108 проверок тем/контраста, минимум 4.682:1, без нарушений axe color-contrast. Редактор сохранил 3 нажатия после вставки.
- Новый контур: 46 проверок отображения/контраста на 390/430/1280 px, обе схемы и ручной переключатель. Дополнительно: административные категории/инструменты, документ с вложением, восстановление черновика, сбой/повтор, явный выбор при одновременной правке, старые категории в URL, PDF-просмотр и скачивание. [Машинный отчёт](qa/workspace/report.json).
- Финально повторены проверки избранного, документов, старых ссылок, фильтров категорий, скачивания, шрифтов и текста 200%. Нет ошибок страницы или горизонтального переполнения в проверенных сценариях.

Браузерная эмуляция не заменяет проверку физического iPhone/Android, встроенного MAX и российских мобильных сетей. Перед публикацией остаются визуальная приёмка, задания собственников, разрешение владельца и обычный PR с зелёным CI.
